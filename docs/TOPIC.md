## 1. 주제 한 줄

**"가상 창고형 약국의 근무 직원을 위한 업무 지원 자동화"** — 직원 · 어르신 손님이 묻는 것을 약국 문서로 답하고, 사람이 정할 일(회수 확인 · 현금 차액 · 복약 판단)은 약사 · 약국장에게 넘깁니다.

**입구 · 뒷단 조합**: A 기본형 · B 메신저 + 헬프데스크형 · C 자체 웹앱형 중 **C 자체 웹앱형** (직원·어르신 화면은 Next.js, 약사 화면은 FastAPI, DB는 PostgreSQL)

- 모든 팀이 함께 쓰는 공통 시나리오는 팀 웹훅과 data-api로 측정합니다(A 기본형과 같은 방식).
- 가산점 항목으로 Slack `#support-alerts` 알림과 Jira 연동을 넣었습니다. Jira에는 시스템 장애 티켓만 보내고 받아 오지는 않습니다. 실제로 보낼지 연습으로만 돌릴지는 스위치 하나로 정하며, 기본값은 연습입니다.

## 3. 범위

| 문의 유형 (4개) | 처리 방식 | 근거 문서 |
| --- | --- | --- |
| 회수 공지가 떴어요 | 근거 + 이관 (긴급, 약사) | `recall-first-response`, `recall-customer-guide` |
| 혼자 하는 첫 마감 | 자동 답변 (현금 차액은 근거 + 이관 → 약국장, 냉장고 온도 이탈은 긴급 → 약사) | `closing-checklist`, `closing-cash-mismatch` |
| 어르신 약 질문 | 자동 답변 (문서 사실 인용 + AI 고지). 같이 먹어도 되나 · 내 경우 → 보완 질문 뒤 약사 이관, 위험 신호 → 긴급 이관 | `senior-cold-sleep-stomach`, `senior-pain-joint`, `senior-safety-signals` |
| 내 접수 건 확인 | 접수 조회 (본인 건만, 연락처 가림) | `request-records-guide` |

- 정의만 하고 꺼 둔 유형: 약이 떨어졌을 때 · 왜 이 금액이에요?
- 본체 워크플로우는 문의 유형이 아니라 처리 방식 4가지로 분기합니다. 그래서 유형을 켜거나 끌 때는 표 한 곳과 문서 묶음만 고치면 됩니다.

**자동 답변하면 안 되는 경우**: 돈 결정 (차액 처리 · 환불 승인), 약 판단(같이 먹어도 되는지, 먹어도 되는지, 복용량, 복용 중단, 보관 온도를 벗어난 약), 처방 조제 여부, 회수 대상 확정과 손님 안내(둘 다 약사가 승인한 뒤 진행), 위험 신호 (숨참 · 가슴 통증 · 출혈 등 → 약사 긴급 + 119 안내), 약국장 전용 규칙을 직원이 물을 때.

**어르신 기능의 단계**: 기본은 `patient_direct` (환자가 직접 묻고 근거 인용 답 — "규제가 풀린 미래를 가정")이고, 제한이 필요하면 `pharmacist_approval` (약사 승인 뒤 전달) 또는 `handoff_only` (답 없이 약사에게)로 `packs/senior/pack.json`의 `level` 한 줄을 바꿔 내립니다. 병용 질문이나 위험 신호를 약사에게 넘기는 기준 단어는 같은 파일의 `handoff_rules`에 있습니다.
